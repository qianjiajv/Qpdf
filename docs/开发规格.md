> 版本 v1.0 · 2026-10-11 · 仓库 [qianjiajv/Qpdf](https://github.com/qianjiajv/Qpdf)

## 1. 产品定义

**一句话**：做一款"单文档 + 功能区（ribbon）"形态的桌面 PDF 编辑阅读软件——文件打开一次常驻窗口，所有操作作用于当前文档，完全离线、免安装、非管理员可用，功能引擎全部开源。

### 1.1 核心体验（不可妥协的交互规则）

1. 文件常驻阅读窗口，**任何操作都作用于「当前打开的文档」**——不再像工具箱式软件那样每个功能单独选一次文件；
2. 功能以顶部 ribbon 标签 + 按钮行呈现（桌面办公软件的标准形态），切换标签不换窗口、不关文档；
3. 操作完成后结果**刷新回同一个阅读窗口**（替换加载新文档字节，可撤销）；
4. 所有数据不出本机，零网络请求（备份推送除外，且为用户手动触发）。

### 1.2 硬约束

| 约束 | 含义 |
|---|---|
| 离线 | 运行期无任何网络请求；PDF.js/字体/cmap 全部本地打包 |
| 免安装 | 产出单文件夹，拷贝/放 U 盘即用；不写注册表、不装服务 |
| 非管理员 | 不写 `C:\Windows`、`Program Files`；可写位置仅限自身目录与 `%TEMP%` |
| 开源优先 | 引擎与库全部选用开源许可（含外壳 QtWebEngine） |

## 2. 技术选型（全 Python 单栈）

| 层 | 选型 | 许可 | 说明 |
|---|---|---|---|
| 桌面外壳 | PySide6 + QtWebEngine（内嵌 Chromium 内核） | **LGPL-3.0** | 引擎随包走，不依赖系统浏览器；离线、免管理员、便于打包 exe；曾选 pywebview（pythonnet 本机双路均死）与系统 Edge --app（不满足换电脑继续使用）均否决（证据见 §8 风险6） |
| 本地服务 | Python 标准库 http.server（127.0.0.1 随机端口） | PSF | 提供前端静态资源 + PDF 字节流 |
| 阅读渲染 | PDF.js（本地打包，ES module 版） | Apache-2.0 | 翻页/缩放/搜索/标注层；已含 cmaps/standard_fonts/wasm |
| 核心引擎 | PyMuPDF | **AGPL-3.0** | 编辑/页面/表单/注释/加密/密文全覆盖 |
| OCR | RapidOCR（中英文模型，ONNX） | Apache-2.0 | 模型 ~15–50MB，离线 |
| 转 Word | pdf2docx | MIT | 文本型 PDF 效果好 |
| 压缩/优化 | qpdf + Ghostscript 便携 exe | Apache/AGPL | 绿色文件放包内 |
| Office 互转（可选） | LibreOffice 便携 | MPL-2.0 | 体积大，默认不做，阶段5 可选 |
| 打包 | PyInstaller --onedir | GPL+exception | 产出=成品文件夹 |

**AGPL 说明**：PyMuPDF 的 AGPL 对"个人内部离线使用"零义务；仅当闭源商用分发时才需购买授权或换 `pypdfium2`（BSD）。引擎层抽象好接口，保留可替换性。

**LGPL 说明**：PySide6 的 LGPL 允许动态链接，PyInstaller 打包时保留 PySide6 DLL 为独立文件（不静态链接进 exe）即满足合规；体积约 +200MB（内嵌 Chromium 内核），符合 §7 体积分档。

**曾考虑并否决**：pywebview（pythonnet 本机双路均死）；系统 Edge `--app`（引擎随系统走，精简系统无 Edge 时不可用）；Tauri+Rust（打包链复杂、与 Python 生态割裂）；内嵌某开源 Java 工具箱类应用（要求 JVM/常驻服务，违反免安装约束）；封装某免费闭源桌面工具（无可改代码）。

## 3. 系统架构

```
┌────────────────────────────────────────────────┐
│ Edge 应用窗口（msedge --app）                  │
│  ┌──────────────────────────────────────────┐  │
│  │ 前端 app/frontend/                       │  │
│  │  ribbon 标签栏 + 按钮行                   │  │
│  │  PDF.js 渲染 canvas（常驻）               │  │
│  └───────────────┬──────────────────────────┘  │
└──────────────────┼─────────────────────────────┘
                   │ http://127.0.0.1:<随机端口>
┌──────────────────▼─────────────────────────────┐
│ PdfToolServer（Python 线程，见 app/server.py）   │
│  静态: /, /static/*, /pdfjs/*                  │
│  API : /api/dialog/open  系统文件框(真实路径)   │
│        /api/doc/bytes    PDF 字节流             │
│        /api/recent       最近文件读写           │
│        /api/ops/<name>   (阶段2+) 文档操作      │
└──────────────────┬─────────────────────────────┘
                   │ 进程内调用
          PyMuPDF / RapidOCR / pdf2docx / 子进程(qpdf, gs)
```

关键决策：
- **文件字节不走任何桥**（大文件慢），走本地 HTTP；仅绑 127.0.0.1。
- **文件对话框走浏览器 File System Access API**（`showOpenFilePicker`/`showSaveFilePicker`）——127.0.0.1 是安全上下文，Edge 支持，拿真实读写句柄；非 Edge 环境降级 `<input type=file>`（读字节不受影响）。
- 操作接口统一签名：入参=当前文档+选项，出参=新文档字节；前端收到后原地重载。

### 7.1 开发模式：框架先行 + 功能块填充（增量交付）

为让用户测试与开发并行（每完成一个功能块即可上手测试，同时继续下一块），采用增量开发：

1. **先搭框架**：窗口 + ribbon 骨架 + 单文档状态管理 + 功能块注册表；未实现的按钮以灰态占位（形先立起来）；
2. **功能块逐个点亮**：每个功能块是独立小模块，实现后注册进框架即可用，不改框架本体；
3. **测试回环**：每完成一块 → 用户双击 `run_dev.bat` 实测 → 反馈与下一块开发同时进行。

**功能块契约**（框架与功能块之间的唯一接口）：

```python
# app/ops/<块id>.py —— 一个功能块一个文件
BLOCK = {
    "id": "pages.rotate",       # 唯一 id
    "tab": "页面",               # 所属 ribbon 标签
    "label": "旋转页面",
    "order": 30,                # 同标签内排序
    "needs_doc": True,          # 无打开文档时禁用
}
def run(doc_bytes: bytes, params: dict) -> bytes:
    """输入当前文档字节 + 前端参数，返回新文档字节。"""
```

- 前端启动拉取 `/api/blocks` → 按标签渲染全部按钮；
- 点击按钮 → `POST /api/ops/<id>`（body=当前文档字节+参数）→ 返回新文档字节 → 阅读器原地重载；
- 块内异常统一捕获回传前端弹提示，不允许拖垮框架。

## 8. 已知风险与边界（诚实版）

1. **精修 PDF 内文字/挪图**：做不到商业级编辑器的所见即所得；只能"删旧字→原位插新字（匹配字体字号）"或覆盖层，80% 场景。
2. **PDF→Excel/PPT**：基础可用，复杂表格还原度一般；转 Word（pdf2docx）效果最好。
3. **扫描件编辑**：非文字层 PDF 只能先 OCR 再编辑；OCR 模型首次打包需联网一次，之后永久离线。
4. **PyMuPDF AGPL**：见 §2；接口层保持可替换（pypdfium2 兜底）。
5. **Edge 内核依赖**：Win10/11（含 LTSC）出厂自带 Edge，被第三方精简系统删掉的情况少见但存在。策略：启动时检测 msedge.exe（3 个标准安装位），找不到则明确提示"请安装 Edge"；阶段4 打包另备可选兜底——若目标机器普遍无 Edge，可加"完整版内置 QtWebEngine 壳"（PySide6 LGPL，+150MB，纯离线自包含），默认版仍用系统 Edge 保持轻量。
6. **pywebview 否决记录**：Windows 下 pywebview 必经 pythonnet；本机 netfx 路径 clr_loader 解析 `Python.Runtime.Loader.Initialize` 失败（重装无效），coreclr 路径可进但其 winforms 后端硬依赖 .NET Framework 专属类型 `System.Windows.Forms.ContextMenu`（.NET 6 中不存在 → TypeLoadException）。两条路均不可修复，故外壳改 Edge `--app` 模式。

## 9. 工程与备份

- **备份机制**：本机直连 `github.com` 被断（仅 `api.github.com` / `ssh.github.com` 通），故备份走 REST 快照推送：双击 `backup.bat`，内容级比对、单次提交。幂等，重复跑显示"已是最新"。
- **token**：fine-grained PAT（仅 Qpdf 仓库 + Contents RW），存放 `data/github_token`（不入库）。
- **SSH 通道**：公钥已挂账号但 GitHub 侧神秘拒绝认证（主机指纹已验证为官方）；留待日后网络变化时重试，非当前依赖。
- **本地 git**：MinGit 2.56 便携版，离线可用；历史与远端快照推送不同源，以远端为备份事实源。
